# 에이전트팀 실습: 주문 정산 버그 추적

작은 주문 정산 프로그램에 원인이 애매한 버그가 하나 있습니다. 먼저 `BUG_REPORT.md` 를 읽으세요.
의심 가는 변경이 다섯 개나 되지만 실제 원인은 하나입니다. 같은 버그를 **서브에이전트** 방식과
**에이전트팀** 방식으로 각각 추적해 보고 차이를 비교하는 것이 이 실습의 목표입니다.

## 준비

```bash
python -m pytest     # 1건 실패, 10건 통과가 정상 시작 상태
python -m shop       # 불일치 주문 목록 확인 (여러 번 돌려 보세요)
```

외부 의존성은 pytest 하나뿐입니다. 실습 A를 마친 뒤에는 저장소 최상위에서
`git checkout -- team-practice-shop` 으로 코드를 원래 상태로 되돌리고 실습 B를 시작하세요.

## 실습 A: 서브에이전트로 조사

Claude Code 에 다음처럼 요청합니다.

> BUG_REPORT.md 의 버그를 조사해줘. 최근 변경 사항 중 의심되는 것들을 서브에이전트에게
> 하나씩 맡겨 병렬로 조사하고, 결과를 모아 원인을 결론 내려줘. 아직 코드는 고치지 마.

관찰할 것:
- 서브에이전트들이 서로의 조사 결과를 알고 있나요?
- 메인 세션이 받은 것은 무엇인가요? (`/context` 로 확인)

## 실습 B: 에이전트팀으로 조사

에이전트팀은 실험 기능이라 버전에 따라 설정이 필요할 수 있습니다. 강사 안내에 따라 활성화하세요.

> BUG_REPORT.md 의 버그를 에이전트팀으로 조사해줘. 팀원 3명을 만들고 각자 다른 가설을
> 맡게 해. 팀원끼리 서로의 가설을 반박하고, 반박을 견딘 가설만 결론으로 남겨줘.
> 아직 코드는 고치지 마.

관찰할 것:
- 팀원끼리 주고받은 메시지 중 결론을 바꾼 것이 있었나요?
- 리드는 언제 개입했나요?
